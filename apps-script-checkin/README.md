# เช็กอินด้วยรหัสทางอีเมล

เป็น Apps Script Web app แยกจาก mailer/confirmation เดิม ทุกอีเมลที่มีลิงก์ของวันนั้นขอรหัสได้ ไม่ตรวจรายชื่อผู้สมัคร ไม่อ่าน Gmail และไม่ส่งอีเมลขณะติดตั้ง

## ติดตั้งครั้งแรก

1. เข้าบัญชี **qiskit.th@gmail.com** แล้วสร้างโปรเจกต์ใหม่ที่ script.google.com (อย่าเขียนทับโปรเจกต์ confirmation ที่มี doGet เดิม)
2. วาง Config.gs และ Code.gs ในไฟล์ Script ตามชื่อ เพิ่ม HTML ชื่อ Checkin แล้ววาง Checkin.html
3. เปิด Project Settings → แสดง appsscript.json แล้ววาง manifest ชุดนี้ในโปรเจกต์ใหม่
4. ตรวจ spreadsheetId และวันที่ใน Config.gs แล้วบันทึก เรียกใช้ **qciSetup_** และอนุญาตสิทธิ์ ระบบสร้างแท็บ QFF_Checkin และ secret ใน Script Properties ไม่เปลี่ยนชีตสมัคร/ประวัติส่งเมลเดิม
5. Deploy → New deployment → Web app → **Execute as: Me (qiskit.th@gmail.com)** → **Who has access: Anyone** (รวมผู้ไม่ลงชื่อเข้าใช้ หากนโยบายบัญชีรองรับ) แล้ว Deploy ผู้เข้าร่วมไม่ต้องขอสิทธิ์อ่านชีตหรือส่ง Gmail
6. เรียกใช้ **qciShowLinks_** ดูลิงก์แยกวันใน Execution log ใช้ลิงก์ /exec พร้อม event และ invite ครบ ห้ามใช้ /dev สำหรับผู้เข้าร่วม
7. ค่าเริ่มต้น testMode: true รับเฉพาะ qiskit.th@gmail.com ทดสอบวันกิจกรรมจริง จากนั้นตั้ง **testMode: false** → Save → Manage deployments → Edit → **New version → Deploy** เพื่อรับทุกอีเมล
8. ส่งเฉพาะลิงก์ของวันนั้นให้ผู้เข้าร่วม คนที่ได้รับลิงก์ส่งต่อก็ใช้งานได้เช่นกัน ลิงก์เป็นสิทธิ์เข้าถึงแบบส่งต่อได้ ไม่ใช่หลักฐานการสมัคร

## การทำงาน

กรอกอีเมล → ส่งรหัส hex 8 ตัว → กรอกรหัสในหน้าเดิม → ยืนยันเช็กอิน เมื่อสำเร็จแท็บ QFF_Checkin แสดง CHECKED_IN และเวลาไทย รหัสหมดอายุ 10 นาที ใช้ได้ครั้งเดียว ผิด 5 ครั้งล็อกรหัส ขอใหม่ห่างกันอย่างน้อย 60 วินาที ไม่เกิน 3 ครั้งต่ออีเมลต่อชั่วโมง รหัสใหม่ยกเลิกรหัสเก่า ทุกอีเมลเช็กอินได้หนึ่งครั้งต่อวันกิจกรรม แต่ใช้ได้อีกในวันอื่น

ระบบเปิดเฉพาะวันที่ใน Config ตามเวลาไทย (00:00–23:59) ต้องแก้วันที่ใน Config และ Deploy เวอร์ชันใหม่หากต้องการซ้อมก่อนวันจริง หน้าเว็บไม่มีการเช็กอินจากการกดลิงก์หรือแค่ขอรหัส ต้องยืนยันรหัสก่อนเท่านั้น

เก็บ **Challenge ID** แยกกับ **Code HMAC** ไม่เก็บรหัสส่งเมลแบบอ่านได้ เช็กอินถูกบันทึกบนแถวเดียวกับ token ที่ใช้แล้ว โดยใช้ Script Lock ป้องกันการยืนยันพร้อมกัน อย่าแชร์ชีตหรือ Script Properties ให้ผู้เข้าร่วม ช่อง Created/Expires เป็น epoch milliseconds; Checked In At แสดงเวลาไทย

**SENDING/REVIEW** ไม่ใช่เช็กอินสำเร็จ หาก API ส่งเมลผิดพลาดจะไม่ลองส่งซ้ำเอง รหัสในสถานะนี้ใช้ไม่ได้ ผู้รับขอรหัสใหม่ตามระยะเวลาที่กำหนดได้ หากเช็กอินแล้วแต่หน้าเว็บขาดการเชื่อมต่อ ให้ผู้จัดตรวจ CHECKED_IN ในชีตก่อน ไม่ลบประวัติเพื่อส่งซ้ำ

## โควตาและข้อจำกัด

Gmail ส่วนบุคคล Apps Script มีโควตา MailApp โดยทั่วไป **100 ผู้รับต่อวัน** และแชร์โควตากับ mailer ที่รันบัญชีเดียวกัน ระบบนี้ตรวจโควตาคงเหลือและตั้งเพดาน 90 คำขอใน 24 ชั่วโมง เผื่อบางส่วนไว้ แต่ไม่รับประกันว่าจะพอสำหรับงานจริงเมื่อมีการขอรหัสใหม่ หากต้องรองรับเกินนี้ควรใช้ Workspace หรือบริการส่งเมลสำหรับธุรกรรมก่อนเปิดใช้งานจริง

ลิงก์ลับช่วยจำกัดการเข้าถึง แต่คนที่มีลิงก์อาจขอรหัสหลายอีเมลจนโควตาหมดได้ ระบบนี้ยังไม่มี CAPTCHA/IP rate limit จึงเหมาะกับกิจกรรมกลุ่มเล็กที่ควบคุมการแจกจ่ายลิงก์ได้ ไม่ใช่บริการสาธารณะขนาดใหญ่ การยืนยันอีเมลไม่พิสูจน์ว่าคนนั้นนั่งเข้าร่วมประชุมจริง และไม่รวม alias ของอีเมล (เช่น +tag) เป็นคนเดียวกัน

หากต้องเปลี่ยนลิงก์ที่รั่ว ให้ผู้จัดลบ Script Property `invite:<event-id>` ของวันนั้นแล้วรัน qciSetup_ ใหม่ ลิงก์วันอื่นและ HMAC secret ไม่เปลี่ยน ลิงก์เก่าจะใช้ไม่ได้

## ทดสอบออฟไลน์

`node --test apps-script-checkin/checkin.test.cjs` ใช้ Sheets, MailApp และเวลาแบบจำลอง ไม่มีการส่งอีเมลจริง
