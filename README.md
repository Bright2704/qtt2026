# Qiskit Fall Fest 2026: Thailand — เว็บไซต์งาน

เว็บไซต์ทางการของ Qiskit Fall Fest 2026: ประเทศไทย
สร้างด้วย **Next.js 15 (App Router) + TypeScript** ผลลัพธ์เป็นไฟล์ static ล้วน อัปโหลดขึ้นเซิร์ฟเวอร์ธรรมดาได้เลย ไม่ต้องมี Node บนเซิร์ฟเวอร์

---

## เริ่มใช้งานใน 3 คำสั่ง

```bash
npm install       # ติดตั้ง dependency
npm run dev       # เปิดดูที่ http://localhost:3000
npm run build     # สร้างไฟล์จริง ผลลัพธ์อยู่ในโฟลเดอร์ out/
```

เสร็จแล้วอัปโหลดทุกอย่างในโฟลเดอร์ `out/` ขึ้นเซิร์ฟเวอร์ จบ

> ใช้ **Next.js 16** (Turbopack) กับ **Node 20.9 ขึ้นไป**
> ถ้าเคยติดตั้งของเดิมไว้ ให้รัน `npm ci` หนึ่งครั้งเพื่อล้างให้ตรงกับ `package-lock.json`
> เวอร์ชันที่ติดตั้งในเครื่องกับที่เซิร์ฟเวอร์ build ต้องตรงกัน ไม่งั้นจะเจออาการ
> "ในเครื่องรันได้ แต่ขึ้นเว็บจริงพัง"

**ชุดทดสอบ** (ต้องเปิด `npx serve out -l 4173` ค้างไว้อีกหน้าต่างหนึ่งก่อน)

```bash
node scripts/contrast-audit.mjs       # ตรวจสีตัวอักษรทุกหน้า ทั้งไทยและอังกฤษ
node scripts/form-test.mjs            # ทดสอบฟอร์มลงทะเบียนตั้งแต่ต้นจนจบ
node scripts/mobile-motion-test.mjs   # ตรวจลูกเล่นและพารัลแลกซ์ฝั่งมือถือ
```

## ระบบสองภาษา

ข้อความทุกจุดเขียนเป็นคู่ `{ th: "...", en: "..." }` ปุ่ม `TH | EN` บนแถบเมนูสลับได้ทันที ค่าที่เลือกจำไว้ในเบราว์เซอร์

**เพิ่มข้อความใหม่:**

```tsx
const { t } = useLang();
<p>{t({ th: "สวัสดี", en: "Hello" })}</p>
```

HTML ที่ build ออกมาเป็นภาษาไทยเสมอ (ดีต่อ SEO ไทย) แล้วสลับเป็นอังกฤษฝั่งเบราว์เซอร์

> ถ้าภายหลังอยากได้ URL แยกภาษา (`/en/...`) ให้เปลี่ยนไปใช้ `next-intl` โครงสร้างข้อมูลปัจจุบันย้ายได้เลยโดยไม่ต้องเขียน copy ใหม่

## ระบบสี

สีทั้งหมดดูดมาจากไฟล์สติกเกอร์ทางการโดยตรง อยู่ที่ `:root` ในไฟล์ `app/globals.css`

**เว็บใช้โทนสว่างอย่างเดียว ไม่มีโหมดมืด** — ตั้งใจให้ตรงกับสติกเกอร์ต้นฉบับของ IBM
ที่ออกแบบมาวางบนพื้นขาว สติกเกอร์จึงเด่นและอ่านง่ายกว่า
พื้นมืดเหลือใช้เป็น section ตัดกันเพียงไม่กี่จุด กับ footer เท่านั้น

| Token | ค่า | ใช้ทำอะไร |
|---|---|---|
| `--indigo-900` | `#1B0E3F` | พื้นมืดสุด hero, footer |
| `--indigo-800` | `#2B145A` | สีแบรนด์หลัก, ตัวหนังสือบนพื้นสว่าง |
| `--lavender-400` | `#B896F8` | accent, ไอคอน, focus ring |
| `--pink-400` | `#ED84B5` | ปุ่ม CTA และ hover เท่านั้น |
| `--ice-100` | `#DCE4F9` | ตัวหนังสือบนพื้นมืด |

### ⚠️ กฎที่ห้ามละเมิด

ตรวจ contrast ตาม WCAG 2.1 แล้ว:

- `--pink-400` บนพื้นขาว = **2.70** ❌ **ห้ามใช้เป็นตัวหนังสือ**
- `--lavender-400` บนพื้นขาว = **2.41** ❌ **ห้ามใช้เป็นตัวหนังสือ**
- `--pink-500` บนพื้นขาว = **3.72** ❌ **ห้ามใช้เป็นตัวหนังสือ**
- ปุ่มพื้นชมพูต้องใช้ตัวหนังสือสี `--indigo-900` (6.95 ✅) **ห้ามใช้สีขาว**

ชมพูและลาเวนเดอร์ใช้ได้กับ *พื้น เส้น ไอคอน* บนพื้นขาว และใช้เป็น *ตัวหนังสือ* ได้เฉพาะบนพื้นมืด

**อยากได้ตัวหนังสือสีชมพูให้ใช้ token คนละตัว**

| Token | ค่า | ใช้ทำอะไร |
|---|---|---|
| `--pink-text` | `#C81264` | ตัวหนังสือชมพูบนพื้นสว่าง (ขาว 5.64 ✅ · ม่วงอ่อน 4.52 ✅) |
| `--grad-cta` | ชมพู → ลาเวนเดอร์ | **พื้นหลัง** เท่านั้น เอามาระบายตัวอักษรไม่ได้ |
| `--grad-cta-text` | `#C81264` → `#6F3CCD` | ไล่สีเดียวกันในเวอร์ชันที่ระบายตัวอักษรได้ |

**ปุ่มบนแถบสีจัด** (เช่น `.cta-band`) ต้องเป็นพื้นทึบเสมอ ใช้ `.btn--solidDark` หรือ `.btn--solidLight`
ปุ่มโปร่งใสบนพื้นสีจัดจะกลืนไปกับพื้นหลังจนอ่านยาก
และ `.btn--ghostDark` / `.btn--onDark` ใช้ได้เฉพาะบน `.section--dark` เท่านั้น

## สติกเกอร์ทางการ และเอฟเฟกต์แบบ Magic UI

### สติกเกอร์

สติกเกอร์ทั้ง 7 ตัวอยู่ที่ `public/assets/stickers/` ถูกตัดออกมาจากสไลด์ Call to Action
ที่ทีมได้รับจาก IBM (ดูรายละเอียดและวิธีเปลี่ยนเป็นไฟล์ความละเอียดสูงใน `README.txt` ในโฟลเดอร์นั้น)

**ปรับองศาและตำแหน่งได้ทั้งหมดที่ไฟล์เดียว: `data/stickers.ts`**

| ตัวแปร | ความหมาย |
|---|---|
| `tilt` | องศาเอียงของสติกเกอร์ (ลบ = เอียงซ้าย) |
| `inset` | รัศมีวงโคจรใน hero — ยิ่งมาก วงยิ่งเล็ก (`1%` = วงนอกสุด) |
| `angle` | องศาเริ่มต้นบนวงโคจร |
| `spin` | เวลาโคจรครบหนึ่งรอบ — ตัวที่อยู่วงเดียวกันต้องใส่ค่าเท่ากัน |
| `bob` | จังหวะลอยขึ้นลง |
| `top` / `left` / `size` / `opacity` | ตำแหน่งและขนาดของสติกเกอร์ตกแต่งที่กระจายในแต่ละ section |

> ⚠️ ตำแหน่ง `scatter` เลือกไว้ให้อยู่ริมขอบที่ไม่มีตัวหนังสือ ถ้าย้ายเข้ามากลางหน้า
> สติกเกอร์จะไปอยู่หลังข้อความและทำให้อ่านยาก

**การปรับสำหรับจอมือถือ** — คุมด้วยตัวแปรใน `app/magic.css` ไม่ต้องแก้ `data/stickers.ts`

| ตัวแปร | ทำอะไร | ค่าที่ใช้ |
|---|---|---|
| `--o-scale` | ย่อสติกเกอร์ที่โคจรทั้งวงพร้อมกัน | `0.82` เมื่อจอ ≤ 560px |
| `--ring-scale` | คูณกับ `inset` เพื่อถ่างวงโคจรออก | `0.62` (≤900px) · `0.36` (≤560px) |

`--ring-scale` จำเป็นเพราะ `inset` เป็นเปอร์เซ็นต์ พอกรอบเล็กลงรัศมีก็หดตามไปด้วย
วงในจึงเข้าไปซ้อนเหรียญตราจนสติกเกอร์โดนบัง ค่านี้ดึงวงในให้ถ่างกลับออกมา
ตอนนี้ที่ความกว้าง 390px เหลือช่องว่างระหว่างเหรียญกับสติกเกอร์ที่แคบที่สุด **44px**
ตรวจอัตโนมัติได้ด้วย `node scripts/mobile-motion-test.mjs` (วัดตลอดหนึ่งรอบการหมุน ไม่ใช่แค่จังหวะเดียว)

### ฟอร์มลงทะเบียนที่ใช้งานได้จริง

`components/RegisterForm.tsx` เป็นฟอร์มเต็มรูปแบบ ไม่ใช่แค่หน้าตา
มีตรวจความถูกต้องฝั่งเบราว์เซอร์ครบ (ช่องบังคับ รูปแบบอีเมล การยอมรับข้อปฏิบัติ)
พร้อมเลื่อนและโฟกัสไปที่ช่องแรกที่กรอกผิดให้อัตโนมัติ

ฟอร์มทำงาน **สองโหมด สลับให้เองจาก `data/site.ts` → `contact.formEndpoint`**

**โหมดทดลอง** (ค่าเริ่มต้น ตอนที่ `formEndpoint` ยังว่าง)

เดินครบทุกขั้นเหมือนของจริง — ตรวจข้อมูล → หน่วงเหมือนกำลังส่ง → ออกรหัสอ้างอิง
(`QFF26-SUT-7K3M`) → หน้ายืนยันพร้อมตารางสรุปคำตอบทั้ง 13 ข้อและเวลาที่ส่ง
ข้อมูลเก็บใน `localStorage` ของเบราว์เซอร์เครื่องนั้นเท่านั้น ไม่ได้ส่งออกไปไหน
มีแถบสีม่วงบอกชัดว่าอยู่ในโหมดทดลอง จะได้ไม่มีใครเข้าใจผิดว่าสมัครสำเร็จแล้ว

บนหน้ายืนยันกดต่อได้ทั้ง **ส่งข้อมูลนี้ทางอีเมล** (เปิดโปรแกรมอีเมลพร้อมข้อมูลครบ)
และ **คัดลอกข้อมูล** ส่วนบนฟอร์มมีปุ่ม **กรอกข้อมูลตัวอย่างให้** สำหรับทดสอบรวดเดียว
กับ **ดาวน์โหลด CSV** (มี BOM ให้ Excel เปิดภาษาไทยไม่เพี้ยน) เอาไว้ดูว่าเก็บครบจริง

**โหมดจริง** — ใส่ URL ที่ `contact.formEndpoint` แล้วจบ ไม่ต้องแก้โค้ด
รองรับ Formspree, Basin, Web3Forms หรือ API ของทีมเอง (รับ POST เป็น JSON)
แถบโหมดทดลอง ปุ่มข้อมูลตัวอย่าง และการเก็บลง localStorage จะหายไปเองทั้งหมด

ถ้าอยากใช้ Google Form แทนฟอร์มนี้ ใส่ลิงก์ที่ `contact.registerForm`
แล้วเว็บจะสลับไปฝัง Google Form ให้เอง

**ทดสอบฟอร์ม**

```bash
node scripts/form-test.mjs
```

ไล่ทดสอบ 33 ข้อ ตั้งแต่กดส่งทั้งที่ยังไม่กรอก อีเมลผิดรูปแบบ การบล็อกเมื่อยังไม่ยอมรับ
ข้อปฏิบัติ ไปจนถึงรหัสอ้างอิงไม่ซ้ำ ใบสรุปครบทุกแถว สองภาษา จอมือถือ และโหมดปิดอนิเมชัน

### พารัลแลกซ์ — มีสามแบบ ทำงานพร้อมกันได้

**ตามการเลื่อนจอ** — `data/stickers.ts` ช่อง `speed` (ขึ้นลง) และ `drift` (ออกข้าง)
แต่ละสติกเกอร์ตั้งค่าไม่เท่ากัน เวลาเลื่อนจึงค่อย ๆ แยกออกจากกัน ไม่ใช่เลื่อนเป็นก้อนเดียว
บนจอแคบกว่า 760px จะคูณความเร็วเพิ่ม 1.75 เท่าอัตโนมัติ เพราะจอมือถือสูงน้อยกว่า
ระยะที่สติกเกอร์วิ่งผ่านสายตาจึงสั้นกว่ามาก ถ้าใช้ค่าเดียวกันจะรู้สึกเหมือนไม่ขยับเลย

**ตามเมาส์** — `components/magic/PointerLayer.tsx` ครอบอะไรก็ได้แล้วให้ขยับตามเคอร์เซอร์
ค่า `depth` คือระยะขยับสูงสุดเป็นพิกเซล ใช้ lerp ไล่เข้าหาเป้าหมายทีละ 8% ต่อเฟรม
จึงลื่นไม่กระตุกตามเมาส์ตรง ๆ และปิดเองบนอุปกรณ์สัมผัสที่ไม่มีเคอร์เซอร์

**ตามแรงปัดจอ** — `components/magic/ScrollSway.tsx` วางไว้ใน `app/layout.tsx` ตัวเดียวทั้งเว็บ
วัดว่าผู้ใช้ปัดเร็วแค่ไหนแล้วเขียนค่า `−1..1` ลงตัวแปร CSS `--scrollv` ที่ `:root`
ตัวนี้มีไว้แทนพารัลแลกซ์ตามเมาส์บนมือถือโดยเฉพาะ เพราะโทรศัพท์ไม่มีเคอร์เซอร์

| ใช้ที่ไหน | ทำอะไร |
|---|---|
| `.scatter__item` | เอียง ±11° ตามจังหวะปัด |
| `.orbit__art` | สติกเกอร์ที่โคจรเอียง ±15° |
| `.orbit__center` | เหรียญตราเอียงสวนทาง ∓4° ให้รู้สึกมีน้ำหนัก |
| `.hero__orbit` | ทั้งวงขยับขึ้นลง ±18px |

ปัดแล้วค่าจะพุ่งขึ้นทันที พอหยุดปัดจะค่อย ๆ กลับเข้า 0 ในราวหนึ่งในสามวินาที
แล้วลูป rAF หยุดเอง ไม่กินแบตตอนผู้ใช้อ่านอยู่เฉย ๆ
ถ้าระบบตั้ง `prefers-reduced-motion` ไว้ ตัวนี้ไม่ทำงานเลยตั้งแต่ต้น

ส่วน `Scatter.tsx` รวมทั้งสองแบบไว้ในลูป rAF เดียว ตัวที่พารัลแลกซ์เร็วกว่า
จะตอบสนองเมาส์แรงกว่าด้วย ให้รู้สึกว่าอยู่ชั้นความลึกเดียวกัน

> ⚠️ อย่าครอบ element ที่มี animation บน transform อยู่แล้ว (เช่นสติกเกอร์ที่ลอยขึ้นลง)
> ให้ครอบตัวแม่แทน ไม่งั้น transform จะตีกันแล้วภาพกระตุก
> นี่คือเหตุผลที่ `.scatter__slot` (รับพารัลแลกซ์) กับ `.scatter__item` (รับการเอียงและลอย)
> ต้องแยกเป็นคนละชั้น

### เอฟเฟกต์ Magic UI

ทำเป็น CSS ล้วนใน `app/magic.css` + คอมโพเนนต์ใน `components/magic/`
**ไม่ได้ลงแพ็กเกจ Magic UI จริง** เพราะมันต้องใช้ Tailwind กับ framer-motion
ซึ่งแปลว่าต้องรื้อสไตล์เดิมทั้งหมดและเพิ่ม dependency อีกหลายร้อยตัว
เอฟเฟกต์ที่ได้เหมือนกัน แต่ bundle ยังเบาเท่าเดิม

| ไฟล์ | เอฟเฟกต์ | เทียบกับ Magic UI |
|---|---|---|
| `OrbitingStickers.tsx` | สติกเกอร์โคจรรอบเหรียญตราสองวง หมุนสวนทางกัน | Orbiting Circles |
| `StickerMarquee.tsx` | แถบสติกเกอร์เลื่อนไม่รู้จบ เอาเมาส์ชี้แล้วหยุด | Marquee |
| `Reveal.tsx` | เนื้อหาค่อย ๆ ปรากฏพร้อมเบลอจางตอนเลื่อนถึง | Blur Fade |
| `NumberTicker.tsx` | ตัวเลขสถิตินับขึ้นเมื่อเลื่อนมาเห็น | Number Ticker |
| `Spotlight.tsx` | ไฟสปอตไลต์ตามเมาส์บนการ์ด | Magic Card |
| `.beam` ใน magic.css | เส้นแสงวิ่งรอบขอบการ์ดตอน hover | Border Beam |
| `.btn--shimmer` | ประกายวิ่งผ่านปุ่ม CTA | Shimmer Button |
| `.shine` | หัวข้อ hero ไล่สีเคลื่อนไหว | Animated Gradient Text |

ทุกเอฟเฟกต์เคารพ `prefers-reduced-motion` — ผู้ใช้ที่ตั้งค่าลดการเคลื่อนไหวจะเห็นเนื้อหาครบ
โดยไม่มีอนิเมชัน (ทดสอบแล้ว: `.reveal` ทั้ง 22 จุดแสดงผลปกติ ไม่มีหน้าว่าง)

**ถ้าอยากใช้ Magic UI ตัวจริงในอนาคต** ต้องลง Tailwind CSS แล้วค่อย ๆ ย้ายสไตล์
คอมโพเนนต์ในโฟลเดอร์ `magic/` ถอดออกได้ทีละตัวโดยไม่กระทบส่วนอื่น

Facebook และ LinkedIn อ่าน SVG ไม่ได้ ต้องแปลงเป็น PNG ก่อน:

```bash
npx sharp-cli -i public/assets/og-image.svg -o public/assets/og-image.png resize 1200 630
```

แล้วเปลี่ยน path ใน `app/layout.tsx` จาก `og-image.svg` เป็น `og-image.png`

## Accessibility

ทำตามมาตรฐาน WCAG 2.1 ระดับ AA แล้ว:

- Contrast ผ่านทุกคู่ตามตารางด้านบน
- Focus ring ชัดเจนทุกจุดที่กดได้ (`3px --lavender-400`)
- Mega menu และเมนูมือถือใช้คีย์บอร์ดได้ครบ กด `Esc` ปิดได้
- Skip-to-content link เป็นอย่างแรกในหน้า
- Countdown ตั้ง `aria-live="off"` ไม่ให้ screen reader อ่านทุกวินาที และมีข้อความวันที่แบบ static คู่กัน
- รองรับ `prefers-reduced-motion`
- Touch target บนมือถือ ≥ 44×44px

**อย่าลืมทดสอบ** ด้วยคีย์บอร์ดล้วน (ไม่แตะเมาส์) ทุกครั้งที่เพิ่มหน้าใหม่
